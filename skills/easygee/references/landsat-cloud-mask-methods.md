# Landsat Cloud-Mask Method Selection

This is a compact method reference for Landsat 8/9 cloud screening. It is not
a course. Use it to choose a safe default, explain trade-offs, and avoid
confusing masking with cloud-underlying-image reconstruction.

## Default for current Earth Engine workflows

- Use `LANDSAT/LC08/C02/T1_L2` (or the corresponding Landsat 9 collection).
- Apply the Collection 2 scale factors separately from cloud masking.
- Use the product's `QA_PIXEL` bitmask for fill, dilated cloud, cirrus, cloud,
  cloud shadow, and—when snow is not the target—snow.
- Use `QA_RADSAT == 0` as the default additional mask for radiometrically
  saturated pixels; relax it only when the target requires those pixels.
- `QA_PIXEL` is the operational quality result generated from the CFMask
  family. In practice, the agent normally reads this band rather than
  reimplementing CFMask.
- A scene property such as `CLOUD_COVER` is only a scene-level filter; it is
  not a pixel cloud mask.
- A mask removes or hides contaminated pixels. It does not reconstruct the
  ground reflectance beneath a cloud.

The current Collection 2 pattern is documented in the Earth Engine migration
guide. Older examples may use Collection 1 `pixel_qa`; do not copy that band
name into a Collection 2 workflow.

## What the main tutorials actually demonstrate

### Collection 1 to Collection 2 migration

The [Earth Engine migration guide](https://developers.google.com/earth-engine/landsat_c1_to_c2)
is the most useful implementation reference. Its `QA_PIXEL` expression is a
short, reproducible baseline for cloud and shadow masking. It is a code
reference, not an accuracy benchmark.

### SimpleLandsatCloudScore

The [Earth Engine API reference](https://developers.google.com/earth-engine/api_docs#eealgorithmslandsatsimplecloudscore)
describes `ee.Algorithms.Landsat.simpleCloudScore` as a simple cloud-likelihood
score for Landsat TOA imagery. Earth Engine explicitly says it is not a robust
cloud detector and is mainly for relative comparison between looks. Use it for
quick previews or as a teaching baseline, not as the default for Collection 2
Level-2 production analysis.

### Visual composite tutorial

The [Clouds and Image Compositing tutorial](https://google-earth-engine.com/Interpreting-Image-Series/Clouds-and-Image-Compositing/)
shows the useful visual lesson: scene-level filtering alone can leave clouds;
adding `QA_PIXEL` and `QA_RADSAT` improves the composite, while stricter
filtering can reduce data availability and create gaps. The result is a
cleaner composite, not recovered values in a single cloudy observation.

## What validation research says

The USGS [CFMask description](https://www.usgs.gov/landsat-missions/cfmask-algorithm)
describes a multi-pass, decision-tree-based algorithm that also projects cloud
shadows using estimated cloud height. It warns about bright targets, snow/ice,
thin clouds, and cloud-shadow uncertainty.

In the USGS [operational Landsat cloud-algorithm comparison](https://www.usgs.gov/publications/cloud-detection-algorithm-comparison-and-validation-operational-landsat-data-products),
the evaluation used Landsat 8 scenes across biomes and cloud-cover conditions
and found CFMask plus its confidence bands had the best overall accuracy among
the tested operational methods. AT-ACCA was the strongest nonthermal option.
This supports CFMask as the default, but it is not a guarantee that it wins in
every biome or for every thin-cloud/snow case.

For reproducible accuracy work, use a cloud-truth dataset such as the USGS
[Cloud Cover Assessment validation data](https://www.usgs.gov/landsat-missions/cloud-cover-assessment-validation-datasets)
and report omission/commission or precision/recall, not only a visual map or
the number of retained pixels.

## When the user asks for cloud-underlying-image reconstruction

Route this as a separate gap-filling or data-fusion task. The [HISTARFM GEE
tutorial](https://developers.google.com/earth-engine/tutorials/community/histarfm-cloud-and-gap-free-landsat)
demonstrates a preprocessed, monthly 30 m Landsat time series generated by
fusing Landsat and MODIS with a bias-aware Bayesian data-assimilation method.
It is not a replacement for `QA_PIXEL`, is limited by available regional
assets, and should not be presented as an observed value under a cloud.

## Agent decision rule

1. For current Landsat 8/9 C2 L2 analysis, choose `QA_PIXEL` first.
2. Use `QA_RADSAT == 0` with the default EasyGEE mask; state explicitly when
   saturation is retained for a special target.
3. Use `simpleCloudScore` only when the user explicitly wants a quick TOA
   score, a legacy comparison, or a teaching contrast.
4. If the user says “去云后填补空洞” or “重建云下影像”, explain that this is
   a second-stage temporal/fusion reconstruction problem and ask for a target
   (single scene, seasonal composite, or continuous time series).
5. For teaching or QA, show the raw image, mask, masked image, valid fraction,
   and a multi-date composite; do not infer accuracy from appearance alone.
